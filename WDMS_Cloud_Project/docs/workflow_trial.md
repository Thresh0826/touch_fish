# 一键工作流开发测试 v7：明确任务凭证与模块边界

工作流修订为 `one-click-steps-v7.5-network-login-wait`，导航为 `native-navigation-v9-page-wait`。首次或名单变化时直接读取本轮实际名单，生成Excel后再核对。v7将编排放入core/native_workflow.py，采集规则与窗口适配、日志、进程监督和报表服务分开；GUI和命令行通过CollectionRequest调用同一采集业务。旧阶段入口由stage_invocation兼容，不改变一键界面。精确源码版本见SOURCE_MANIFEST.json。

## 一键流程

基础运行条件检查 → 启动或复用已登录WDMS → 自动导航 → 只读实际货主下拉列表 → 按本轮名单逐货主查询 → 保存Excel，之后人工核对名称和数据。

运行前检查Windows环境、配置的.exe、现有报表依赖和报表目录写入能力。名单在进入实际检索页后获取，默认不读取源码目录的native_trial_owners.json。业务范围仍为完整24个不同货主；数量、名称或可读性不符则不查询。高级命令行显式指定--owners时保留旧基准文件校验，并支持UTF-8 BOM；GUI默认不使用这条路径。

owner_discovery在受监督子进程中检查配置程序身份、实际检索页、下拉控件父客户区及可用状态，连续读取两次完整名单；一致才保存本轮owners_snapshot.json。它不抢焦点、不选择货主或点击查询。快照包含名单摘要、配置上下文和当前WDMS进程/主窗口身份；父进程同时要求快照和明确完成记录。新任务不复用旧阶段文件。

每轮读取当前实际24项名单并校验快照来源、摘要及配置上下文，直接进入采集。新一轮名字或顺序变化时采用本轮读取的名单；不依赖confirmed_owners.json，不创建确认缓存，不显示名单窗口，也不为名单确认暂停运行提示。旧确认文件保留在本机，不需要迁移或删除。

快照字节摘要传给每个查询子进程；同一轮中名单文件变化、WDMS进程/窗口变化、主窗口被弹窗禁用或现场名单变化仍会停止，不使用不一致的数据继续查询。取消仍有效；输出表的名称与数据由用户事后核对。

WDMS未启动时，按原逻辑自动启动并登录；已显示登录窗口时仍只提交一次登录。只有一个配置程序、无登录窗口、主窗口可用且页面证据通过时，才复用现有会话，不读取凭据、不抢焦点、不再次提交密码。页面证据包括真实检索页、实际显示的已登录菜单标记，或用户截图确认的“企业管理”侧栏与其“员工与用户”标签父链。窗口身份、实际父客户区及复用前状态需重新核对；无法确认则停止，不擅自关闭或重启客户端。

复用的是当前已登录账号，没有独立核对它与配置账号相同。现场复测前确保当前WDMS登录的是目标账号。桌面主界面只提供“一键运行”流程，单独登录/导航/采集入口已移除；内部模块和命令行诊断仍保留。

导航须按“在库管理 → 在库查询展开 → 在库商品检索”确认实际页面，已有页面可直接确认。详细裁剪及鼠标检查见 `navigation_trial.md`。

检索页切换后的标签读取WinError=1460可在页面等待期限内只读重扫，原主窗口须保持同一身份并通过探活；每次丢弃失败扫描，不重复菜单点击。名单获取阶段也采用这项机制，完整确认页面后再读取名单。持续失败、权限拒绝、窗口变化或取消时仍不进入后续阶段；page_scan_deferred是中间等待记录，只有正常退出和最终完成记录才能交接。

## 阶段确认与失败处理

自动登录、导航、读取、采集四个阶段使用步骤执行器。读取必须正常退出且恰有一条完成记录，快照校验后记录owners_plan_ready并直接采集。终止错误保留原类型和阶段；可恢复的健康等待不覆盖实际成功。原生动作期限、取消和不重复输入规则保持，不自动重试登录、点击或查询。

错误汇总只采用真正终止事件，query_settle_read_unavailable、health_wait等已恢复观察不能代替最终原因。每个采集子进程记录退出码，stderr保存为owner_XX.stderr.txt；采集子进程启用Python故障栈记录。即使启动失败或崩溃前来不及记录probe_error，父进程也按实际退出码记录TRIAL_WORKER_EXITED；正常退出却缺少与本轮任务一致的结果凭证则为TRIAL_WORKER_UNCONFIRMED。采集成功以退出码和owner_XX.result.json为依据，凭证绑定worker、任务、货主索引及名单摘要；失败凭证保留原原因，日志仅用于诊断。

本轮新建native_trial目录的owner_XX.jsonl、owner_XX.stderr.txt和trial_error.jsonl复制到flow_…/collection。复制不包含名单快照、配置、Excel或业务结果JSON；复制失败单独记录，原始采集记录仍在报表目录，不覆盖此前业务错误。旧轮次或不唯一的新目录不用于归档。

采集完成须有本轮结果清单、正确行数及待人工核对标记；报告必须来自本轮新建的唯一采集目录，旧报表不能代替新结果。日期在本轮开始时固定，结果清单同时核对任务编号和该日期，跨午夜时仍使用本轮日期。重新打开Excel检查工作表、三列表头、所选3或24个货主的顺序、行数与非负数值，拒绝损坏、缺行、错序或公式数据。结构正确仍不证明现场库存及结果货主独立验证通过，保留人工核对要求。

若运行提示清理失败，单独记录，不覆盖此前的业务错误；已保存的测试表保留，但不把提示清理异常当成正常结束。

## 空闲时现场复测

关闭旧Demo，将完整源码包解压到新文件夹，保留旧目录、现有Windows Python环境和报表。无需复制名单JSON，双击新WDMS_Cloud_Project目录的启动Demo.bat。本机配置和凭据继续沿用。

保持唯一目标账号WDMS、未最小化、无其他弹窗；未启动时一键流程可自动启动登录。首次选“前 3 个货主”并点“一键运行：登录并生成表格”，运行期间不操作键鼠。期望自动读取名单、查询前三个货主并生成三列表格，全程无名单确认弹窗；在Excel核对货主名称和现场数值后再测24个。名单在新一轮变化时也自动使用最新名单；同一轮中变化仍停止，取消仍有效。

桌面不再提供分阶段或模拟演示按钮。“打开运行日志”打开本机workflow_logs，“打开报表目录”打开配置的报表目录；都不启动或重试业务流程。源码内部的诊断函数和回归测试继续用于开发排查。

流程证据：`%LOCALAPPDATA%\WDMSInventoryDemo\workflow_logs\flow_*`。同一根目录还有本轮 `console_*.txt`；采集证据和Excel在配置的报表目录 `native_trial_*` 下。

在Windows PowerShell执行：

```powershell
explorer.exe "$env:LOCALAPPDATA\WDMSInventoryDemo\workflow_logs"
```

v7回传本轮flow.jsonl、collection目录及对应console记录；按故障阶段补充login、navigation或owners主日志（不选_scan）。日志可能含真实名称及数量，仅回传允许交接、必要时脱敏的材料，owners_snapshot.json留本机。旧v5不会自动归档采集记录，需从报表目录对应native_trial_…另取owner_*.jsonl。
