## 已修复

1. `scripts/run_inventory.bat` 切换到项目根目录再查找 Python 与 main.py。
2. 新增只读 `scripts/check_environment.py`；Real 父进程及工作进程检查自身令牌，Low/Untrusted 明确报错。可见进程数量只作警告，不以少于 20 单独判定失败。
3. 通过匹配进程路径、唯一顶层主窗口后按 HWND 连接；连接异常保留异常类型及数字错误码。发现同名进程但无法读取路径时不重复启动客户端。
4. 主窗口及登录窗标题使用完整正则匹配；主窗口排除有 owner 的窗口。
5. 控件扫描默认深度 6、700 节点，可配置，跳过大型网格和树的后代，保留硬时限。
6. 四个采集控件 ID 按配置使用，不再固定为历史值；四个必须互不相同，证据控件仍独立。
7. 增加 `existing_session` 手动登录模式及独立配置模板，无需配置自动登录凭据；原模板和旧配置仍兼容自动登录。
8. 补齐登录标记文本来源；成功标记可来自主窗口或登录窗，并允许延迟出现；登录窗消失后不再读取失效的失败标记。
9. transition 策略在旧货主结果仍显示时也记录 busy，最终仍要求 idle 和结果归属匹配。
10. 测试使用系统临时目录；跨进程锁测试改用真实子进程标准输出，避免 multiprocessing.Queue 的命名管道依赖，同时验证释放后能重新获取锁。

## 没有采用的建议及原因

- `--output-dir` 已优先于 `real_output_dir`，本项未发现代码缺陷。
- version 是真正的刷新代次，不能配置为汇总数量。汇总同值不代表真正的代次相同，也不能将库存变化作为唯一完成证据。
- 不以货主下拉框当成结果货主标记；下拉框只能证明输入条件，不能证明旧结果已被新查询替换。
- 不以数值稳定或固定等待充当查询完成证据。不无条件拒绝全零库存，因为真实零库存合法。
- 未凭空设置 confirmed=true，未填入未知导航、会话和查询控件。
