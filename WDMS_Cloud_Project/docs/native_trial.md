# 原生库存采集与物流库存表

当前入口为完整源码包中的 `WDMS_Cloud_Project/启动Demo.bat`，选择前3个或全部24个货主后点击“一键运行：登录并生成表格”。使用包内所有模块，不再逐个覆盖scripts文件。保留旧源码目录、已有Windows环境和报表；无需复制真实名单JSON，程序会读取本轮实际货主下拉列表。详细步骤见包外Windows_PowerShell操作说明.md。

程序依次核对本轮名单、窗口身份、货主名称和索引，发送一次Alt+F，观察等待光标结束，再等待整件数与散件数稳定5秒并完成三次采样。查询输入不自动重发；部分输入只释放程序按下的键或鼠标按钮。输入意图日志写完后再次核对目标，最后检查与SendInput之间不进行文件写入、休眠或重试。

查询前显示等待光标或光标不可见时，最多等待20秒。每次检查WDMS前台、按钮身份及指针命中；窗口或指针变化时停止，恢复后复核货主与名单摘要。事件为query_idle_wait、query_idle_recovered及query_idle_wait_timeout。

时间预算集中于core/query_policy.py：准备40秒、查询前空闲等待20秒、查询90秒、进程收尾10秒；默认每货主监督上限160秒，工作流采集预算为所选数量乘160秒再加60秒报表时间。内部阶段同时服从剩余的monotonic期限和取消请求，外部仍用子进程实施硬期限。单次查询仍为90秒，稳定等待与三次采样包含在其中。

原生控件扫描只对结构化文本读取WinError=1460做有界只读重扫，使用最后一次完整扫描返回的数据，不从累计诊断日志重建控件列表；权限拒绝、身份变化和不完整结构直接停止。探活仍最多等待约15秒，不触发额外查询。

整件数、散件数为必需数据，分别按非负整数与非负Decimal严格解析；小数不截断、不四舍五入。合计仅为可选诊断，缺失、读取失败或显示格式变化均不参与最终一致性判断。三列表头保持货主、整件数、散件数。

本轮开始时固定报表日期，文件名、工作表名、结果清单及回读均使用同一日期。结果保存在配置报表目录的 `native_trial_时间_标识/x年x月x日物流库存.xlsx`；另有trial_results.json。本轮独立任务目录避免覆盖旧报表。

每个子进程发布owner_XX.result.json，包含协议版本、本轮编号、独立worker编号、货主索引、名单摘要及完成/失败状态。父进程要求退出码0及与本任务一致的完整凭证；诊断日志出现完成文字不代表采集成功。文件通过临时文件发布，短暂PermissionError做有界重试，既有凭证不覆盖；错误输出保存为owner_XX.stderr.txt。

逐货主JSONL、stderr及trial_error.jsonl归档到本轮flow_…/collection；结果凭证、名单快照、配置和Excel不进入回传白名单。失败后停止本轮，不自动重跑；只回传允许交接的日志。

结果没有独立货主标记，选中货主一致及光标稳定不能证明结果归属。所有输出保留requires_manual_review=true和result_owner_independently_verified=false；未放宽main.py正式Real模式的验证要求。Windows实际效果仍需用户现场核对。
