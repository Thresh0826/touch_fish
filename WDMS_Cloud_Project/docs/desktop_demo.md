# WDMS 一键库存采集 Demo

这是可运行的 Windows 桌面 Demo，不是已完成的无人值守版本。

主界面只提供“一键运行：登录并生成表格”，范围可选前3个或全部24个货主。辅助按钮为打开报表目录、打开运行日志、修改设置；单独登录、导航、采集和模拟演示按钮已移除。内部模块与开发回归测试保留，现场使用完整流程。

## 启动

完整解压源码包到新文件夹，打开其中WDMS_Cloud_Project并双击“启动Demo.bat”。优先使用同目录.venv；缺少时使用%USERPROFILE%\wdms_real_test\WDMS_Automation\.venv\Scripts\python.exe。保留旧目录、现有环境及报表，不逐文件覆盖。

当前 Python 必须包含 tkinter/Tcl；如报告 tkinter 缺失，应使用 Windows 官方 Python（安装时启用 Tcl/Tk），或使用在 Windows 构建后的 exe。源代码 Demo 复用现有 Python 环境；最终 exe 版本不要求其他电脑安装 Python。

## 已实现

1. 四步首次配置：选择 WDMS 程序、账号密码、报表目录、确认保存。
2. 文件路径与输出目录写入权限检查。
3. 密码写入当前用户的 Windows 凭据管理器；普通 JSON 只存账号、路径和凭据目标名。
4. 下次启动直接进入主界面；可修改设置，密码留空保留原凭据，更换账号需重新输入密码。
5. 打开报表目录和一键流程日志目录。
6. 一键调用前3/24货主流程，运行期间主界面隐藏，提示非阻塞；停止或完成后显示结果。
7. 同一 Windows 用户配置只允许一个 Demo 实例，避免重复启动。
8. 一键自动登录/复用会话、导航和采集；实际名单从WDMS读取后直接继续，首次或变化时也不弹窗。生成Excel后核对名称与数据，默认无需native_trial_owners.json。当前流程见workflow_trial.md。

配置位置：%LOCALAPPDATA%\WDMSInventoryDemo\settings.json。
一键流程日志和本轮console_…txt保存在同目录workflow_logs，每轮flow_…下有flow.jsonl及各阶段子目录。
真实采集结果与逐货主证据放在用户选择的报表目录下，每轮一个 native_trial_* 子文件夹。
报表目录下每轮native_trial_…包含owner_*.jsonl及可能存在的trial_error.jsonl。故障排查需要这一轮采集记录和对应一键流程记录，名单快照留本机。

## 这次现场验收

1. 初次启动出现配置向导，完成配置后进入主界面。
2. 关闭并重新启动，确认跳过向导，路径与账号仍在。
3. 在 Windows 凭据管理器查看对应 WDMSInventoryDemo: 目标；settings.json 不含密码。
4. 选择前3个货主并点一键运行，期望自动完成登录/复用会话、导航、名单读取及采集；期间不要操作键鼠。

## Windows 上打包

在 Demo 项目目录使用已安装的 Windows Python 运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\build_demo.ps1 -PythonPath 'C:\Users\123\wdms_real_test\WDMS_Automation\.venv\Scripts\python.exe'
```

构建脚本安装 PyInstaller、openpyxl 和 psutil，并检查 tkinter。打包结果：dist\WDMS_Inventory_Demo\WDMS_Inventory_Demo.exe。
必须分发整个 WDMS_Inventory_Demo 文件夹（包含 _internal），不能只复制 exe。
构建时不收集本机配置、凭据或报表。目标机第一次启动仍须配置。

云端本次验证了设置持久化、密码不落 JSON、凭据失败不明文降级、既有采集逻辑和打包子进程入口。Windows 窗口显示、真实凭据存储及 exe 构建仍需 Windows 现场验收；云端未生成或宣称已验证 exe。

## 后台登录与开发诊断

原v2单独登录入口已从主界面移除，登录由一键流程调用。本机配置保留，无需再次填写已保存的密码。单独诊断函数仅用于开发排查，现场不需要分阶段启动。
登录输入框诊断只记录控件元数据和是否密码样式，不读取密码输入框内容，密码不进入日志。
一键入口已串联导航、名单读取和采集，仅在前阶段校验通过后继续。

登录修复：根据各部门右侧下拉框的原生可用状态判断是否选中。已选中的部门保留，未选中的才点击左侧标签，并等待最多 15 秒确认下拉框可用；无法确认则停止，不重复点击。三个部门全部确认后，才填写账号密码、等待最多 30 秒登录按钮可用，并只提交一次登录。无需配置部门名称或选择下拉框选项。

v5 启动状态稳定检查：首次判断前只读观察至少 5 秒，并要求三个下拉框可用状态连续稳定 2 秒（状态变化重置稳定计时，最多等待 30 秒）。每次补选后再次等待稳定；鼠标移入后、发送标签按下消息前复查下拉框可用状态，已恢复选中则取消点击。该等待规则用于减少启动异步恢复状态引起的误操作，实际可靠性仍需 Windows 连续登录测试确认。
